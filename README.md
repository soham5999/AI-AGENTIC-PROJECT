# AI Agent for Vehicle Maintenance Prediction

## Overview
This repository contains a complete beginner-friendly academic prototype combining supervised machine learning with a deterministic tool-using agent. It predicts whether **maintenance may be required**, identifies threshold-based possible concerns, recommends an action, stores history in SQLite, and creates a simulated alert.

> **Important:** The dataset is synthetic and educational. The output is decision support, not a mechanical diagnosis. A qualified technician must verify all recommendations.

## Features
- Reproducible 3,000-record synthetic dataset (`random_state=42` conceptually via NumPy seed).
- Logistic Regression, SVM, Random Forest and Gradient Boosting comparison.
- Accuracy, precision, recall, F1, confusion matrices, model selection by highest F1.
- Modular `VehicleMaintenanceAgent` with validation, ML, diagnosis, recommendation, SQLite memory and alerts.
- Streamlit dashboard, model charts, history search and optional OpenAI explanation layer.

## Architecture and workflow
`Vehicle input -> validation -> predict_maintenance -> diagnose_vehicle -> generate_recommendation -> SQLite memory -> alert_tool -> human technician review`

The ML model produces the structured prediction. The agent orchestrates tools around it; an optional LLM only explains already-produced structured facts and never replaces the classifier.

## Installation
```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate | macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```
The OpenAI package is optional. Install `pip install openai` and add a key to `.env` only if a natural-language explanation is desired. Never commit `.env`.

## Generate, train and run
```bash
python data/generate_dataset.py
python models/train_model.py
streamlit run app.py
```
The training command creates `models/saved_model.pkl`, `visualizations/model_metrics.csv`, charts and confusion-matrix data. Metrics are generated by actual evaluation, not hard-coded. The application can create the SQLite database automatically.

## Dataset and validation
Features are vehicle age, mileage, engine temperature, oil quality, brake wear, battery voltage, tire pressure, service gap, previous repairs and vibration. Bounds are enforced in `utils/preprocessing.py`. This dataset is not representative of real vehicles and should not be used for operational decisions.

## Database design
`maintenance_history(id, vehicle_id, timestamp, parameters, risk_probability, maintenance_prediction, diagnosis, recommendation, priority)`. Parameters and findings are stored as JSON text for a simple portable SQLite implementation.

## Example input
`VH-001, age=5, mileage=80000, temperature=98, oil=70, brake wear=40, voltage=12.4, tire pressure=32, service gap=180, repairs=2, vibration=3`.

Example output fields: prediction (`0/1`), risk probability, selected model, priority (`LOW/MEDIUM/HIGH`), possible concerns, recommendation and simulated alert. Exact values depend on the trained model and are intentionally not fabricated here.

## Limitations and future scope
Synthetic labels are rule-generated, sensor quality and calibration are not modeled, class thresholds are educational, and no physical inspection occurs. Future work includes real validated fleet data, temporal models, calibration, drift monitoring, technician feedback, authentication, deployment monitoring and optional SHAP (feature association is not causality).

## Academic disclaimer
This project is for CA3 learning purposes. “Possible concern” and “inspection recommended” must not be interpreted as proof that a component failed. Model selection for deployment requires independent validation, calibration, engineering requirements and real vehicle data.
